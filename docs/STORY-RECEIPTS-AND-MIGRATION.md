# Подтверждение сюжетных действий и перенос зон

Обновлённый клиент не меняет `Bridge.snapshot` из `StoryRuntime.commit/fire`.
Он отправляет серверу только ключ события и номер запроса. Сервер проверяет свой
каталог, позицию, условия и Once, сохраняет изменение через прежний Store,
отправляет snapshot и результат. Только COMMITTED разрешает локальную презентацию.
Старые нетранзакционные реплики без условий, Once и actions сохраняют прежний путь.

Повторная доставка одного номера не повторяет actions даже для повторяемого события.
Сервер хранит последние 32 результата на соединение; более старые номера отклоняет.
Номер нельзя повторить с другим ключом. Новый запрос ограничен прежним бюджетом
16/20 тиков; переподключение создаёт новую сессию, а сохранённый Once остаётся в Store.
На клиенте может ожидать один запрос: повтор через 20 тиков с тем же номером,
отказ по тайм-ауту через 100 тиков. Поздние/повторные ответы игнорируются.
Выход, смена мира и story reset очищают ожидание. Выбор второй реплики блокируется
до результата первой; закрытый или сменившийся экран не получает старую презентацию.

Это не распределённая транзакция сцены. Если клиент отключился после сохранения,
серверный прогресс остаётся сохранённым, а презентация может быть пропущена.
Восстановление/доставка сцен после перезахода относится к будущему серверному Director.
При недоступном серверном канале нет возврата к небезопасному локальному commit.

## Перенос старых сюжетных триггеров

```sh
python tools/migrate_story_triggers.py cutscene_triggers.json --scenes cutscenes --dialogues dialogues.json --output candidate-story-events.json
```

Каталог версии 2 сохраняет исходные ключи, Once, условия и действия. Сервер отслеживает пересечения хитбокса при входе и выходе, включая старое правило трёх блоков для однослойной зоны. Первая позиция после подключения задаёт исходное состояние. Уход с нужной стороны границы отменяет задержку. Для NPC нужен UUID доступной для взаимодействия сущности. Именованный сигнал выдаёт сервер через `/whiteout story-authority signal <игрок> <имя>` или подтверждённую реплику с `director_signal:`.

Переносчик читает достижимые выборы из авторского файла диалогов и сохраняет их индексы. Сервер разрешает варианты после подтверждения предыдущего события. Выбор расходует разрешение на все соседние варианты. Разрешение действует 1200 игровых тиков и сбрасывается при переподключении. Завершённый Once хранится в прежнем Store. Сохранение незаконченной презентации относится к блоку 5.

Звук, радио, диалог и проверенные сцены с одним событием DIALOGUE воспроизводит клиент после подтверждения. Действия над целью применяются в серверной транзакции и требуют существующего определения цели в мире. Для сцен с командами или несколькими событиями, автоматических ответов и NPC без UUID требуется авторская проверка. Переносчик отказывает всему кандидату при неподдерживаемой записи. Он пропускает отключённые триггеры и сохраняет существующий выходной файл.

Оператор сверяет кандидат с авторским сценарием и объединяет его с уже существующим
серверным каталогом, сохраняя чужие события. Rules копируются без переинтерпретации;
окончательная валидация выполняется существующим `StoryRules.validate` при загрузке.
После установки в `<world>/whiteout-story-events.json` выполнить
`/whiteout story-authority reload` и `status`: invalid=false и ожидаемое число событий.
При ошибке каталог целиком отклоняется; сохранённый прогресс не переписывается.

Реальные авторские файлы карты в проверенной ветке не обнаружены. Поэтому
автоматический перенос конкретной карты не объявляется выполненным.

## Проверки

StoryReceiptsTest проверяет повторную доставку, смену ключа, вытеснение из кеша,
лимит запросов, тайм-аут, поздние ответы и reset. StoryAuthorityTest проверяет
прямоугольные границы, once-only и визуальное событие без записи Store.
CLIENT probe загружает реальные Mixins и сравнивает 80 граничных позиций с
бинарным Trigger.contains. SERVER probe проверяет новые сетевые кодеки.
Python проверяет реальный переносчик, отказ от неподдерживаемых триггеров,
сохранность существующего файла и отсутствие частичного результата.

Эти проверки не заменяют прохождение карты, Duo с задержкой и графическую проверку.
