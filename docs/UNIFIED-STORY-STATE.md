# Сохранение сюжета мира и игрока

Старые каталоги и сохранения используют WORLD. В каталоге версии 3 событие может задать `"scope":"PLAYER"` и необязательный `"checkpoint":"camp"`. UUID берётся у участника серверного запроса. Условия по переменным, Once, действия, цели и проверки завершения событий читают выбранную область. Погода, зона и устройства читаются из мира. Общий Director использует WORLD.

В файле мира `whiteout-zones.json` старые поля сохраняют общий сюжет, а `playerStory` хранит личную запись под UUID. Сервер записывает переменные, смену цели, выполненный выбор и контрольную точку одной операцией. Координаты точки берутся у игрока на сервере. Ошибка записи откатывает изменения в памяти. Версии мода до этого изменения при сохранении не сохраняют новое поле. Перед откатом версии нужна копия мира.

Клиент видит общую историю и собственные значения. Используйте отдельные имена для общих и личных переменных, целей и точек, если обе области должны отображаться одновременно. При совпадении имён в интерфейсе приоритет у личной записи. Существующие команды редактирования checkpoint сохраняют проверку прав и творческого режима. При загрузке личной точки отметки уже выполненных Once сохраняются. Обычные повторяемые действия остаются повторяемыми.

## Восстановление

`/whiteout story-authority store-status` проверяет состояние основного файла и загружает резервную копию тем же валидатором. При повреждении либо пропаже основного файла с оставшимися следами записи Store блокирует сохранение. Временный файл сам по себе не подтверждает успешную транзакцию.

Оператор может выполнить `/whiteout story-authority recover-backup` для повреждённого мира. Команда оставляет копию повреждённого оригинала рядом с миром, проверяет резервный файл, затем атомарно заменяет основной. Для продолжения требуется перезапуск. Восстанавливается состояние на момент создания резервной копии. Более поздние подтверждения и внешние награды, которых в копии ещё нет, требуют сверки автором перед продолжением.

Серверный тест Fabric использует временную папку, два UUID и реальный Store. Игровой проход через GUI редактора, телепортация на checkpoint и отключение питания компьютера проверяются отдельно.
