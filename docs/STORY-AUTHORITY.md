# Серверная авторизация сюжетных запросов

Изменение P0 для ветки roadmap на базе 3.13.0. Базовый `STORY_COMMIT` принимал
произвольные conditions/actions клиента. Проверка синтаксиса StoryRules не являлась
авторизацией. Теперь существующий обязательный серверный Mixin перехватывает
запрос до оригинального обработчика и до истории редактора.

## Контракт

Обновлённый клиент посылает `story_request` с ключом и номером запроса и ждёт
`story_reply` до запуска презентации. Подробности и переносчик зон:
[STORY-RECEIPTS-AND-MIGRATION.md](STORY-RECEIPTS-AND-MIGRATION.md).

Для совместимости сервер также принимает прежний `WhiteoutActionPayload("STORY_COMMIT", ...)` с JSON
`{"key":"имя_события"}`. Остальные поля старых пакетов, включая actions,
conditions и once, игнорируются. Сервер читает определение из
`<мир>/whiteout-story-events.json`, проверяет живого игрока, отсутствие spectator,
измерение, расстояние, серверные StoryRules и серверный Once. Даже оператор не
может использовать этот пакет для непроверенной записи произвольных действий.

Пример формата (инструментальный пример, не готовый сюжет и не включается автоматически):

```json
{
  "schema": 1,
  "events": [{
    "key": "author:approved_event",
    "once": true,
    "area": {"dimension": "minecraft:overworld", "x": 0, "y": 72, "z": 0, "radius": 3},
    "conditions": [{"variable": "chapter", "operator": "EQ", "value": {"type": "INT", "integer": 1}}],
    "actions": [{"variable": "chapter", "operation": "SET", "value": {"type": "INT", "integer": 2}}]
  }]
}
```

Нужно использовать реальные ключи и координаты утверждённых сценариев.
Файл содержит **разрешения и определения**, а не копию прогресса. Общие переменные
и завершённые ключи остаются в существующем `Store.Data` / `whiteout-zones.json`.
Вся цепочка StoryRules вычисляется перед записью; ошибка сохранения откатывает
ссылки на прежние переменные и completedEvents в памяти. Синхронизация выполняется
после успешной записи. Once использует прежний ключ, поэтому уже завершённые
события не повторяются. На серверном потоке второй игрок видит результат первого.

`/whiteout story-authority status` показывает число определений и ошибку чтения.
`/whiteout story-authority reload` перечитывает файл; обе команды требуют уровень 2.
Нет автоматической записи defaults, исправления повреждённых файлов или доверия
к импортированным с клиента сценариям. Некорректный каталог полностью блокируется.
Лимиты: 128 событий, 256 КиБ файла, 8192 байта запроса, 16 запросов на соединение
за 20 тиков на канал, радиус до 128 блоков или точный прямоугольник со сторонами
до 256 блоков. Новый канал передаёт ключ до 128 символов вместо JSON.
Предупреждение игроку/в журнал — не чаще 200 тиков.
Кеш каталога сбрасывается по reload и завершению сервера; сессии — при disconnect.

## Совместимость и оставшаяся работа

- Схема старого сохранения не меняется; ничего не удаляется и не мигрирует автоматически.
- **Клиентские STORY_COMMIT требуют серверного каталога.** Без него запрос отклоняется,
  включая одиночную игру. Автор должен перенести утверждённые ключи, условия и
  действия из сценарных файлов. Это необходимое изменение доверительной границы.
- Прямые старые запросы изменения целей/отметок событий, checkpoints, актёров/NPC
  и редактора требуют оператора уровня 2 и сохраняют дополнительные прежние проверки.
  Обычный creative сам по себе больше не разрешает изменение общего мира.
- Серверная LakeStory и серверные электрические события не проходят через этот
  клиентский запрос и сохраняют прежний путь. Диалоги без изменения состояния,
  оборудование и команды с штатной проверкой прав продолжают прежний путь.
- Серверный каталог пока поддерживает переменные StoryRules, WORLD Once и область.
  Это не весь Unified Story State: PLAYER-scopes, серверные определения целей,
  полный Director и миграция клиентской библиотеки остаются следующими этапами.
- Не заявляется полная безопасность всех старых пакетов мода: остальные отдельные
  сетевые каналы требуют дальнейшего аудита. Игровой запуск ещё обязателен.

Проверки: `regressionStoryAuthorityTest`; стандартные `check`, Foundation и Fabric
route probes. Фактические результаты текущего запуска приведены в итоговом отчёте.
