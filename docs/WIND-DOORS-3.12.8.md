# Whiteout — ветка исправления ветра и аудит дверей (для 3.12.8)

Основа: актуальные исходники Whiteout 3.12.7 с последним исправлением баррикад.

## Ветер

**Что обнаружено в исходниках:** предыдущий серверный обработчик проверял `WorldAtmosphere.weather(world, player.getBlockPos())`, тогда как игрок наблюдает метель с высоты камеры; на границе Y-зоны эти положения могут отличаться. Каждые 10 тиков обработчик также сбрасывал эффект в момент, когда игрок не стоял на земле. Это возможные причины отсутствующего/нестабильного замедления — без игрового теста нельзя утверждать, что именно они объясняют наблюдение пользователя.

**Изменения:** погодную зону сначала читаем по высоте глаз, затем по ногам; прыжок не сбрасывает состояние ветра; обновление раз в 5 тиков, квантование штрафа до 1%; сервер использует направление ветра из уже существующей `GroundSnowPolicy`, не меняя её; максимальное замедление повышено с 8% до 15%; оставлены исключения для Creative, spectator, транспорта, полёта, воды и укрытий. Используется синхронизируемый ванильный атрибут скорости, без принудительного перемещения игрока.

**Новая команда диагностики:** `/whiteout-wind status` (выполнять в Survival через ~1 секунду после начала движения). Она сообщает причину отсутствия эффекта либо применённый процент. Существующая команда `/whiteout atmosphere wind-movement true|false` сохранена.

## Двери и засовы

Проведена проверка реализации `AutoClosingDoors`, `ElectricDoors`, `DoorBolts`, `DoorBoltApi` и `AutoDoorPolicy`. Подтверждено по коду: срок ожидания 210 тиков (~10,5 секунд), двери с привязкой к электросети Whiteout исключены; занятость проёма живыми сущностями и сигнал редстоуна блокируют автозакрывание; закрытие выполняется через ванильный `DoorBlock.setOpen`, не изменяя файл состояний засовов. Код дверей не менялся, чтобы не привносить ненужные регрессии. Автоматические проверки фиксируют этот контракт.

**Ограничение:** несовместимые модовые двери, не наследующие `DoorBlock`, этим механизмом не поддерживаются. Закрытый засов при принудительном открытии дверного блока внешним модом/редстоуном может разблокироваться в текущей логике `DoorBolts.sweep` — это существующее поведение, не часть настоящего патча.

## Проверки

- Java 21: `AutoDoorAndWindPolicyTest` — 18 утверждений, успешно.
- Статические контракты Wind/Doors/Bolts — 13 утверждений, успешно.
- Java 21 синтаксис: 132 файла успешно разобраны `JavacTask` (НЕ компиляция с Fabric/Yarn).
- Общий `tests/check_resources.py` имеет устаревшее ожидание 8 вариантов `barricade.json` вместо текущих 36 **уже в исходной 3.12.7**. Не меняли тест баррикад, поскольку это зона работы другого ИИ.

## Игровые тесты (копия мира)

1. `/whiteout atmosphere wind-movement true`, активная метель, Survival; бегите по направлению шлейфов позёмки и против него.
2. Введите `/whiteout-wind status` после секунды движения — сравните статус и процент штрафа. Если отображается «нет зоны», пришлите текст и координаты границы зоны.
3. Прыгайте во время бега; эффект не должен отключаться только из-за прыжка.
4. Зайдите в укрытие или под крышу; штраф должен обнулиться. Выйдите на открытую территорию — должен появиться снова.
5. Проверьте выключение `/whiteout atmosphere wind-movement false`, Creative, полёт, плавание.
6. Откройте ванильную дверь — через 10–11 секунд закрывается. Встаньте в проём, поставьте NPC, подайте сигнал редстоуна — не должна зажимать/ломать сценарий.
7. Проверьте дверь, привязанную к сети Whiteout — не должна автозакрываться.
8. Установите засов, заприте дверь, перезайдите; штатное автозакрывание не должно удалять засов.

**Версию мода не повышали**: это изолированная ветка для последующего объединения в 3.12.8.
