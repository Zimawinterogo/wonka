# Whiteout 3.12.17 — «Тьма у озера»

Исправлена сцена из предоставленного патча 3.12.16 поверх ветки
`feature/winter-crisis-foundation` (исходный коммит `a0b5fb8`). Minecraft Fabric
1.21.1, Java 21. Итоговый файл — полный merged-JAR, не промежуточный overlay.

## Изменения

- Единственный старт: `8381 72 8366`, ±3 по всем трём осям, по входу.
  На новом сохранении загрузка внутри области считается первым входом.
  После reset находящийся внутри игрок обязан выйти и войти снова; ожидание
  сохраняется по UUID и не снимается выходом другого игрока.
- Запертая дверь засчитывает попытку использования либо прицеливание с расстояния
  до трёх блоков. Успешного открытия не требуется.
- Домашний генератор принимает настоящую канистру штатным способом. Только три
  серверно проверенных рывка после заправки дают неудачную попытку. Мотор остаётся
  выключенным. Щиток требует эту попытку и использование/прицельный осмотр.
- Старый генератор `8355 72 8436` защищён до обработки топлива, в обработчике
  взаимодействия, стартерном пакете и включении мотора. Другие миры без включённой
  конфигурации сцены не затрагиваются.
- Резерв остаётся на `8375 76 8414`. Существующие привязки `circuit_2` и `circuit_3`
  сохраняются. Сценическое питание лесопилки следует за реальным питанием
  `circuit_3`; сломанный генератор лесопилки не включается.
- Только четыре цели. Заголовок выезжает за 0–0,5 с, описание раскрывается
  на 0,5–1,2 с, исчезновение — 8,3–9,5 с. Интерполяция использует render tickDelta.
  Замена карточки занимает 0,25 с. Пауза останавливает её время.
- Окна `8410 80 8383` и `8410 81 8383` проходят проверку типа и отсутствия BE,
  сохраняются отдельно, исчезают без дропов. Звук стекла идёт из окна, громкость 4,
  затем через 35 игровых тиков отправляется финальная реплика. Новых целей нет.
- Все пользовательские реплики сохранены дословно. Диалоги используют оригинальный
  немодальный HUD Whiteout. Очистка ограничена ID `lake_scene_line`.

## Команды и журнал

Операторские команды (уровень 2):

```text
/whiteout lake status
/whiteout lake reset
```

`status` показывает этап, UUID ожидающих выхода, заправку, число рывков,
неудачную попытку, реальное состояние резерва, фазу финала, блоки обоих окон,
текущую цель и конфликт/ошибку. Не подгружает чанки и не изменяет мир.

`reset` восстанавливает только записанные в журнал сцены окна и декорации,
если текущий блок соответствует результату изменения сцены. Чужую замену
сохраняет и сообщает число конфликтов. Сбрасывает этапы, свои карточки/реплики,
останавливает три сюжетных генератора и опустошает домашний. Резерв НЕ получает
нового топлива; предохранители, канистры и предметы повторно не выдаются.
Обычная цель Whiteout и конфигурации привязки сетей не сбрасываются.

Журнал и прогресс находятся в `whiteout-lake-scene.json`, запись через временный
файл и атомарную замену. Повреждённый файл сохраняется; сцена отключается.
Запись намерения предшествует изменению блоков. В трёх точках (состаривание,
стекло, reset) выполняется сохранение чанков перед отметкой завершения.
Это не запись каждый тик; на большом мире задержку сохранения нужно оценить в игре.
Обычные тики не подгружают чанки принудительно. Reset оператора может загрузить
ограниченный набор затронутых чанков. Завершённые изменения при relog не накладываются
заново на последующие постройки. При отсутствующем стекле или конфликте финал ждёт.

Прогресс общий для мира; сцена не создаёт независимый эпизод для каждого игрока.
Сравнение владения основано на точном BlockState: внешнее изменение на совершенно
такое же состояние блока невозможно отличить от оставленного сценой состояния.

## Автоматически проверено

- `compileJava`, `check`: 26 регрессионных программ, включая 512 проверок
  координат, переходов, условий топлива/попытки, целей, времени анимации и reset.
- `LakePersistenceTest`: настоящий DTO сцены, старый формат, UUID rearm,
  resetPending, заправка/попытка и четыре фазы финала переживают JSON round-trip.
- `foundationTests` через Fabric SERVER: 32 настоящих BlockState стеклянных
  панелей, разные состояния двух окон, отклонение повреждённого свойства;
  также существующие проверки баррикад, WorldState и Crisis.
- `assembleWhiteout` и `verifyLakeRelease`: реальные классы итогового JAR,
  порядок защиты перед изменением топлива, bootstrap, native HUD routing,
  версия, наличие базовых файлов; 33 базовых data/audio-ресурса идентичны.
- ZIP карты, хеши неизменённых файлов, NBT обеих половин двери, генераторов,
  опор, окон, отсутствие старого резерва, сохранение аудио.

Это не автоматическое прохождение Minecraft. Не проверены живое использование
канистры и стартерного GUI, все 12 шагов в клиенте, слышимость при пользовательской
громкости, Iris/BSL, масштабы GUI, пауза, два игрока, relog и выгрузка чанков в игре.
Жёсткое завершение процесса между сохранением фазы и отправкой звука/реплики не
моделировалось: отметка отправки не является подтверждением получения клиентом.

## Сборка

```text
gradlew.bat -I qa/lake-release.gradle compileJava check verifyLakeRelease
gradlew.bat -I qa/foundation.gradle foundationTests
```

Нужны исходные личные `music_slot_1.ogg` … `music_slot_7.ogg` в существующей
игнорируемой папке ресурсов. Не заменять их плейсхолдерами. При Windows-ошибке
`Unable to establish loopback connection` указать короткий доступный каталог через
`-Djdk.net.unixdomain.tmpdir=...` и `-Djava.io.tmpdir=...` в JAVA_TOOL_OPTIONS.
Старый `BUILD_3.12.8.bat` оставлен как совместимое имя, теперь ожидает 3.12.17.
Сборщик сохраняет оригинальные байты JSON при различии только форматирования;
реальные изменения существующих data/audio по-прежнему отклоняются.

## Проверка владельцем — около 10 минут

1. Открыть отдельную распакованную копию карты с полным JAR 3.12.17 вместо 3.12.16.
2. Выполнить reset на мостике: остаться внутри, убедиться в тишине; выйти и войти.
3. Подойти к двери: она закрыта, звучит реплика и появляется первая карточка.
4. Пустой генератор и щиток не должны продвинуть сцену. Вставить собственную
   канистру; заправка сама по себе не даёт реплику «Мда блять».
5. Сделать три рывка: двигатель не работает. Осмотреть щиток — цель лесопилки.
6. Старый генератор лесопилки проверить канистрой, второй рукой и shift:
   предмет не тратится, UI не появляется. Обычный генератор вне сцены работает.
7. Осмотреть щиток лесопилки и реально запустить возвышенный резерв:
   свет/дверь работают, появляется «Вернуться к дому».
8. Войти в дом: реплика о гнили, пауза, разбиваются два верхних окна,
   затем финальная реплика. Дропов и пятой цели нет.
9. Перезайти: финал не повторяется. Сделать reset дважды: окна с исходными
   соединениями и только сценические декорации восстановлены, чужая цель осталась.
10. Повторить карточку на другом GUI scale/с Iris и без него; отдельно проверить
    паузу, второй клиент и уход из чанков до финала. Эти варианты могут потребовать
    больше десяти минут.
