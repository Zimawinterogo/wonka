# Серверные цели, условия мира и фазы кризисов

Это расширение существующих StoryRules/ObjectiveRules/Store и WinterCrisisDirector.
Новый параллельный файл прогресса не создаётся. Клиентские пакеты передают только
ключ/номер запроса; все приведённые ниже определения принадлежат серверу.

## События и цели

Старые события `whiteout-story-events.json` остаются совместимыми. Добавлены
необязательные поля `objectives`, `world`, `serverOnly` и `scenes`.

Пример `objectives` для выдачи задания (это пример формата, не утверждённый текст карты):

```json
"objectives": [{
  "id": "restore_power",
  "event": "START",
  "definition": {
    "id": "restore_power", "title": "Восстановить питание",
    "status": "INACTIVE", "hidden": false,
    "conditions": [], "onStart": [], "onUpdate": [], "onComplete": [], "onFail": []
  }
}]
```

Поддержаны START, UPDATE (`text`), COMPLETE и FAIL. Определение используется только
при отсутствии цели; уже существующая авторская цель не перезаписывается обычным
START. Повторный START активной цели и повторный COMPLETE/FAIL соответствующего
конечного состояния не повторяют награды/hooks. COMPLETE/FAIL требуют активную цель.
В цепочке сначала выполняются story actions, затем до 16 objective actions в порядке
массива. Проверяются условия и ограничения прежнего ObjectiveRules.

Цель, её производные `objective.<id>.*`, story variables, Once и уведомление старого
ObjectiveHud сохраняются одной записью Store. Ошибка любой операции или записи
откатывает всю цепочку. Если цепочка содержит несколько видимых переходов, HUD
показывает последний, согласно существующему snapshot-контракту.

Для явно заданного сброса цели используется `{"id":"...","reset":true,
"definition":{...}}` без `event`. Definition должна быть INACTIVE. Этот путь
восстанавливает именно указанную цель и её status-флаги, не запускает hooks и
не меняет чужую активную цель. Прочие авторские переменные восстанавливаются
явными actions reset-события.

## Условия мира

`world` — дерево ALL / ANY / NOT / COMPARE. Пример:

```json
"world": {
  "op": "ALL",
  "terms": [
    {"op":"COMPARE","metric":"PLAYER_COUNT","compare":"GE","value":1},
    {"op":"COMPARE","metric":"NETWORK_POWERED","id":"author_network","compare":"EQ","value":1}
  ]
}
```

EQ, NE, LT, LE, GT, GE сравнивают конечные числа; булевы наблюдения представлены
0/1. Поддерживаются PLAYER_COUNT (живые nonspectator в текущем измерении),
TIME_OF_DAY (0..23999), NETWORK_POWERED, GENERATOR_RUNNING, GENERATOR_FUEL (тики),
FUSE_INSERTED, FUSE_BURNT, BLIZZARD, WIND_STRENGTH, SNOWFALL, SHELTER_PROTECTION,
COLD_LEVEL, ZONE_ACTIVE, OBJECTIVE_ACTIVE/COMPLETED/FAILED и EVENT_COMPLETED.
Для устройства задаётся `address: {dimension,x,y,z}`, для сети/зоны/цели/события — `id`.
Переменные и этапы продолжают использовать прежние StoryRules conditions/actions.

Максимум 64 узла, глубина 8, до 16 дочерних условий. Одинаковые атомы внутри
проверки читаются один раз. UNKNOWN не превращается в TRUE через NOT. Выгруженные,
отсутствующие и только закешированные устройства не разрешают событие. Cold Level
пока UNKNOWN: накопленный холод старого мода клиентский и не подменён оценкой сервера.
Проверка выполняется при запросе/переходе фазы, без сканирования блоков мира.

## Шесть фаз в существующем Director

`<world>/whiteout-crisis-scenes.json`, schema 1, до 8 сцен и 256 КиБ:

```json
{
  "schema": 1,
  "scenes": [{
    "id": "author_scene", "dimension": "minecraft:overworld",
    "priority": 50, "armTimeout": 1200, "resetEvent": "author:reset",
    "phases": [
      {"phase":"PREPARATION","event":"author:prepare","ticks":100},
      {"phase":"ONSET","event":"author:onset","ticks":100},
      {"phase":"ESCALATION","event":"author:escalate","ticks":100},
      {"phase":"CRITICAL","event":"author:critical","ticks":100},
      {"phase":"RESOLUTION","event":"author:resolve","ticks":100},
      {"phase":"AFTERMATH","event":"author:aftermath","ticks":100}
    ]
  }]
}
```

Все шесть событий должны существовать в серверном story-каталоге, иметь
`serverOnly:true`, `once:true`, правильное измерение и различные ключи.
События фаз нельзя разделять между сценами. Внутри фазы запрещены вложенные
scene requests. Сумма длительностей — максимум 72000 тиков. Сам каталог сцены
не включает Winter Crisis: нужно явно `/whiteout crisis enable`.

Разрешённое обычное сюжетное событие запускает сцену полем:

```json
"scenes": [{"id":"author_scene","operation":"START"}]
```

Есть CANCEL. Запрос сохраняется в одной транзакции с событием и Once, затем
существующий Director подбирает его из Store. Клиент не может обойти порядок фаз,
отправив ключ serverOnly-события. Первую фазу запускают её условия; следующая ждёт
свой минимальный срок, живого игрока в своей области и свои условия. Условия
предыдущей фазы не проверяются повторно после её успешного выполнения.

`crisis.<id>.phase/active/queued/done/remaining` хранятся в прежних storyVariables. Переход
фазы, её actions/objectives и Once атомарны. При восстановлении выполненные actions
не проигрываются заново; штатная остановка сохраняет остаток времени одной записью
Store. После аварии используется последняя сохранённая точка таймера, поэтому
ожидание может удлиниться, но действия не повторяются. Старые записи без таймера
получают полный срок текущей фазы. Офлайн-время не засчитывается. На пустом сервере
часы Director приостановлены. Смерть/смена измерения
последнего подходящего участника отменяет активную сцену; оператор может возобновить
её с сохранённой фазы. Лимиты: 4 активные сцены, 4 проверки за цикл, до 8 кандидатов
игроков на условие фазы. Остановка сервера сохраняет queued/active для восстановления.
При повреждённых/несогласованных маркерах запуск блокируется с диагностикой.

## Команды и reset

- `/whiteout crisis status` — фазы и причины ожидания/отказа.
- `/whiteout crisis scene <id>` — начать либо возобновить сохранённую сцену.
- `/whiteout crisis scene-reset <id>` — выполнить авторский reset и очистить её курсор.
- `/whiteout crisis cancel` — отмена очереди/активных сцен с сохранением достигнутых фаз.
- Старый `/whiteout crisis test` остаётся технической проверкой World State.
- Старый `/whiteout crisis reset` сбрасывает временный координатор, не весь сюжет.

Все команды требуют op 2. Reset сцены требует отдельного `resetEvent`:
serverOnly=true, once=false, без вложенных сцен и world-условий. Его story conditions,
actions и objective resets проверяются и сохраняются вместе с удалением ключей фаз
и служебных маркеров этой сцены (WORLD). Также освобождаются Once
отдельных стартовых событий, у которых единственный scene request — START этой сцены.
Once общего события, запускающего несколько сцен, не удаляется. Остальные цели,
переменные и события не сбрасываются. Если авторский reset не определён, команда
отказывает вместо попытки угадать обратные действия.

Изменения каталога сцен применяются после перезапуска сервера. Story-каталог можно
перечитать прежней командой; изменение ownership фазы приводит к безопасному отказу.

## Границы готовности

Это рабочий серверный путь для WORLD-сцен с целями и переменными. Полный сценарий
«Чёрная ночь» с плавным освещением/атмосферой, сохранённой камерой и клиентскими
репликами ещё не подключён. PLAYER-scopes и полная история после рестарта
также остаются работой. Реальные сценарии карты
нужно привязать к утверждённым областям и ресурсам; эти примеры не устанавливаются
автоматически и не заменяют авторский сюжет.
