# WhiteoutWorldState 3.12.11

Read-only серверный facade: `dev.whiteout.power.WhiteoutWorldState.of(server)`.
Все запросы выполняются на живом серверном потоке; retained facade после остановки
отклоняет запросы. Серверные callbacks не создают facade, если он никому не нужен.

Методы: `network(id)`, `generator(world,pos)`, `fuse(world,pos)`,
`emergencyLight(world,pos)`, `powerSwitch(world,pos)`, `door(world,pos)`,
`weather(world,pos)`, `shelter(player)`. Возвращают `Reading<T>` с тиком,
availability и Optional immutable record. Коллекции защищены List.copyOf;
внешний код не получает ссылок на Config, Zone или BlockEntity.

`AVAILABLE` — текущее чтение; `CACHED` — сеть использует существующие сохранённые
observed facts выгруженного генератора/щитка; `UNLOADED` — сам чанк недоступен;
`MISSING` — в загруженном месте нет нужного устройства; `UNBOUND` — нет привязки;
`UNAVAILABLE` — повреждённые/неинициализированные данные или отсутствующее измерение.
Ноль топлива не используется как заглушка неизвестного состояния.

## Согласованность

GridManager предоставляет package-private доступ к одной уже загруженной Config.
Он не вызывает lazy load, который при повреждении файла создаёт backup. API
читает BE непосредственно и применяет существующий GridStatePolicy; не вызывает
networkPowered/sampleDevices/persist. Предохранитель, pending stop, flicker и
сохранённые observed facts используют прежние правила. API не меняет топологию,
горючее, настройки, двери, NBT или JSON и не отправляет пакетов.

Кеш сетей — до 128 результатов, TTL один server tick. Existing refreshOne/persist,
DeviceEntity.sync и замена DeviceBlock инвалидируют его, без обратного refresh.
Chunk load/unload и player break инвалидируют оба кеша; chunk callbacks не читают
блоки. ShelterExposure кешируется отдельно на точную позицию глаз/измерение до
5 тиков, максимум 128 результатов. Прочие объекты/зоны читаются заново. Даже
неперехваченное изменение ограничено TTL; expiry проверяется при каждом запросе.
Новых tick loops, обходов всех сетей или forced chunk loads нет.

Снимок сети содержит её зарегистрированные fixtures и вложенные состояния
генератора/щитка. Switch/door views показывают собственную сеть; API не строит
вторую глобальную таблицу привязок. Накопленный холод остаётся `UNAVAILABLE`:
единственный старый meter хранится на клиенте. Shelter view даёт текущие серверные
условия среды, а не точную клиентскую сглаженную величину холода. Погода выбирается
в центре указанного блока, как WorldAtmosphere; для поведения WindMovement при
выборе точки нужно учитывать его eye/feet fallback. Сглаженный переход клиента не
воспроизводится сервером.

## Выполненная проверка

Java 21, Minecraft 1.21.1, Fabric Loader 0.18.4. Релизный JAR не собирался.

```
gradlew.bat --offline --no-daemon --console=plain -I qa/foundation.gradle foundationTests
gradlew.bat --offline --no-daemon --console=plain check
python tests/connected_barricades_test.py
python tests/connected_collision_assets_test.py
```

- compileJava и compileFoundationTests — успешно.
- check — 24 существующих набора успешно (включая реальные Store/DTO persistence,
  независимые сети, генераторы, аварийные лампы, дверные/погодные вспомогательные правила).
- foundationTests — успешно: BarricadeCollisionTest 3276 проверок; BarricadeSupportTest
  114; WorldStateCacheTest 14; WorldStateSnapshotTest 24; WorldStateDeviceTest 12.
- JSON-модели: 3835 проверок соединений; 32 сравнения physical table с shipped models.
- visualRegression на первом этапе — пять существующих наборов успешно.
- audit_resources.py — JSON=153, PNG=39, OGG=42, errors=0; 40 кандидатов на
  неиспользуемые ресурсы являются статическими замечаниями, файлы не удалялись.

Первый прямой JavaExec Minecraft bootstrap падал на IllegalAccessError в реестре.
Исправлен тестовый запуск: FoundationBootstrap использует штатные преобразования
Fabric Knot в SERVER environment. Чтобы старые классы базы не перекрывали overlay,
prepareFoundationBase распаковывает именованную базу в build и исключает совпадающие
overlay .class; исходная база не изменяется. Это НЕ сборка полного релизного JAR.
Тесты реально используют VoxelShape, регистрацию баррикады, callback потери опоры,
DeviceEntity/BackupLampEntity и NBT. Snapshot/cache tests не подменяются заявлениями
о тестировании настоящего ServerWorld.

## Оставшиеся проверки и риски

Не запускались пользовательский мир, реальный dedicated server с финальным merged
JAR, реальные chunk unload/reload и полный рестарт мира, физический выпад предмета
при scheduledTick, игровой рендер с/без Iris/BSL. TTL/инвалидация и NBT reload
проверены отдельно; это не полная проверка lifecycle в живом мире. Финальные ASM
патчи сборки не выполнялись. Fabric bootstrap не вызывает все mod entrypoints и
не заменяет dedicated-server smoke test.

Нагрузка ограничена структурно (кеш до 128, four-neighbour collision, запрос только
одной сети, shelter ray sample до ~260 шагов), но FPS/TPS не измерялись. Частые
уникальные запросы укрытия или копирование очень больших fixture lists требуют
бюджета со стороны будущего потребителя. WorldState не запускает эти запросы сам.
