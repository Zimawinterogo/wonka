# Whiteout — серверные цели и исполняемые фазы кризисов

Дата: 3 ноября 2026. Фактическая версия: **3.13.0**.
Ветка: [feature/whiteout-roadmap-stabilization](https://github.com/Zimawinterogo/wonka/tree/feature/whiteout-roadmap-stabilization).

**Весь мод по исходному roadmap ещё не доделан.** В этом продолжении реализован
связанный блок P0/P1: серверное событие → условия мира → атомарные цели/переменные →
сохранённый запрос сцены → фазы существующего Director → восстановление/reset.
Сборка остаётся промежуточной, не финальным выпуском для пользовательского тестирования.

## 1. Что сделано

- START/UPDATE/COMPLETE/FAIL целей подключены к серверному каталогу. Определения
  берутся с сервера; новые цели используют существующие ObjectiveRules. Повторные
  lifecycle-события не повторяют награды. Есть явный reset выбранной цели.
- Переменные, статус/активная цель, HUD-уведомление, Once и запросы сцен сохраняются
  вместе. Ошибка второй операции или записи Store откатывает всю цепочку.
- Добавлены ограниченные деревья ALL/ANY/NOT и числовые сравнения фактов World State:
  питание, генератор/топливо, предохранитель, погода/ветер/снег, укрытие, зоны,
  время, число живых игроков, статус цели и выполненное событие.
- Неизвестные, выгруженные и только закешированные факты не разрешают событие.
  Клиентский накопленный холод не выдан за проверенный серверный факт.
- Существующий WinterCrisisDirector выполняет шесть управляемых фаз с очередью,
  приоритетом, ожиданием условий и конечным числом запусков. Производственный
  адаптер выполняет story/objective actions, а не только диагностические callbacks.
- START/CANCEL сцены могут приходить из утверждённого сюжетного события. Запрос
  сохраняется с его Once и подбирается Director из Store. Фазы имеют serverOnly
  и недоступны прямому клиентскому запросу. Вложенные запуски сцен из фаз запрещены.
- Прогресс хранится в прежних storyVariables/completedEvents. Фаза и её действия
  атомарны; после восстановления действия не повторяются. Пустой сервер приостанавливает
  часы. При штатной остановке остаток времени сохраняется одной записью, без записи
  каждый тик. После аварии возможна более долгая пауза от последней сохранённой точки.
- Есть диагностика ожидания/ошибок, проверка целостности курсора/Once, возобновление
  сцены и авторский reset. Reset очищает только заданные цели, маркеры/фазы сцены и
  отдельные её стартовые Once; общие события нескольких сцен сохраняются.
- CI сохраняет проверенный полный JAR в артефактах приватного репозитория на 14 дней.
  Музыка включается из прежнего личного JAR и проверяется побайтово.

Форматы и команды: [SERVER-SCENARIOS.md](SERVER-SCENARIOS.md).

## 2. Что уже существовало

Повторно использованы Store, StoryRules, ObjectiveRules, ObjectiveHud/snapshot,
WhiteoutWorldState, WinterCrisisConditions/Director, CrisisSettings и их lifecycle.
Озеро, электрические сети, генераторы, Map Passport, условные диалоги, рюкзак,
геометрия и музыка не переписаны; их регрессии выполняются вместе с новыми.
Нового независимого Story Store, World State или симулятора кризисов нет.

## 3. Что остаётся до «full mod»

| Область | Текущее состояние |
|---|---|
| WORLD-события, переменные, цели, Once | Интегрированный серверный путь готов; миграция реальных сценариев остаётся |
| Условия мира | Основные серверные наблюдения подключены; накопленный холод пока UNKNOWN |
| WORLD Director/фазы | Очередь, фазы, сохранение, отмена/reset работают через существующий координатор |
| PLAYER-прогресс/Duo | Полные персональные scopes и персональная доставка ещё не реализованы |
| История/камеры/реплики Director | История координатора ограничена памятью; сохранение камеры и восстановление клиентской презентации ещё нужны |
| «Чёрная ночь» | Серверный технический путь подготовлен; плавная атмосфера, освещение и утверждённый контент не подключены |
| Реальные карты/старые сценарии | Нужно закончить перенос NPC, SIGNAL, EXIT_BOX, dialogue_choice и сложных клиентских effects |
| Остальные P2–P4 | Monster addon, массовая привязка, Forest/Plot, баланс, редакторы, Radio 2.0 и финальная полировка ещё не объявлены завершёнными |

Авторские привязки должны использовать реальные области и ресурсы карты. Примеры
в документации не устанавливаются автоматически и не выдаются за готовый сюжет.
Ветка всё ещё требует серверного каталога для прежних клиентских сюжетных событий.
Полное прохождение и совместимость всех старых карт не подтверждены.
