# 3.12.12 — deterministic conditions

`WinterCrisisConditions` is analysis only: no tick registration, actions, packets or persistence.
`CrisisWorldSource` reads existing server WorldState and resolves players by UUID for a single cycle.
No second cold, weather, fuel, fuse, power or battery simulation is introduced.

## Contract

Truth is TRUE / FALSE / UNKNOWN with strong Kleene AND, OR and NOT. Only AVAILABLE
facts establish truth. CACHED, UNBOUND, MISSING, UNLOADED and UNAVAILABLE become UNKNOWN,
including under NOT. A caller must explicitly require TRUE before starting anything.
Signals cover blizzard/wind threshold, shelter protection, outage, generator off,
burnt fuse, empty linked backup lamp, electrically locked door, selected active zone,
and leaving an inclusive cuboid in an expected dimension. Missing players or changed
dimensions are UNKNOWN. No client cold meter is fabricated on the server.

`Tracker` uses caller-supplied server ticks: continuous true/false holds, maximum sample
gap, one rising edge per episode. UNKNOWN immediately breaks continuity; it does not
rearm a fired episode. Stable FALSE rearms. A new tracker starts clean after restart.
`Hysteresis` supports separate enter/exit thresholds without changing game balance.
Trackers belong to individual condition/player/network scopes and must be discarded
on disconnect, dimension change, cancellation or stop by their eventual consumer.

## Bounds and ownership

One closeable Cycle shares identical observations, caches exceptions as UNKNOWN,
and charges a fixed sampling budget (1..256). Shelter costs 8 units, network 4,
other observations 1. Maximum 64 distinct probes, depth 16, 128 expression nodes per
evaluation, 32 children per combination. Budget exhaustion is UNKNOWN. These are
work estimates, not milliseconds. Existing WorldState bounds also apply.
Create CrisisWorldSource per cycle; never retain it across cycles. Cycle.close drops
its source and observations. Conditions retain only immutable IDs and addresses.
No world scanning, chunk loading, file writes or event launch occurs.

## Validation

72 deterministic checks in CrisisConditionsTest cover truth combinations, unknown
propagation, stable outages versus flicker, rearming, gaps/restart, independent networks
and player UUIDs, memoization, budgets, errors, unavailable/removed sources, rapidly
alternating zones, and numeric hysteresis. These use controlled sources, not a running
Minecraft server. Existing foundation and regression suites are run alongside them.

Live multiplayer disconnect/reconnect, dimension travel, chunk unload/reload and
real device removal still require an in-game pass. No save schema migration is needed.
The conditions layer intentionally has no scenario runner; that belongs to stage 6.
