# Проверка Duo одним игроком

Установите одинаковый приватный JAR WHITEOUT на клиент и сервер. Режим работает также в одиночной игре с разрешёнными командами. Все команды начинаются с `/whiteout test-duo`. Нужны права оператора уровня 2. Для самого WHITEOUT дополнительный мод для ботов не требуется.

## Первый запуск

1. До включения теста создайте обычную карточку через сюжетную доску. Предмет выдаётся командой `/give @s whiteout:story_board`. Поставьте его на стену 2×2.
2. Выполните `enable confirm`, затем `start`. Оператор становится первым персонажем. Чтобы лично играть за второго, выполните `role second` до запуска.
3. Выполните `ready` от имени бота. Откройте доску и нажмите кнопку старта от имени игрока. Команда `launch` даёт такое же подтверждение из чата.
4. Перемещайтесь обычным способом. Именованный манекен показывает координаты виртуального персонажа. В режиме `follow` координаты совпадают с вашими. Чтобы видеть расстояние до бота, выполните `stay` и отойдите.

У каждой сессии есть настоящий UUID оператора и отдельный стабильный UUID бота. Сервер записывает тестовое прохождение в `<мир>/whiteout-duo-tests/<UUID оператора>.json`. Прочитанные письма, награды, концовки и другие тестовые изменения не попадают в сюжетный Store обычного мира. Инвентарь не получает тестовые награды. Тест читает каталог карты и наблюдает состояние окружающего Minecraft-мира. Строительство, перемещение и собственные административные команды оператора действуют в этом мире как обычно. Для демонстрационного каталога удобнее использовать отдельный мир.

## Управление

| Действие после префикса | Что проверить |
|---|---|
| `enable confirm`, `disable` | Включить изолированный режим или выйти из него. После перезапуска сервера и выхода оператора режим выключен |
| `start`, `stop` | Подготовить участника либо убрать его и закрыть текущую сессию. После stop режим остаётся включённым |
| `role first`, `role second` | Выбрать роль реального игрока до старта нового прохождения |
| `ready`, `launch` | Подтвердить готовность бота, затем начать Duo |
| `follow`, `stay`, `here` | Следовать, удерживать позицию или перенести бота к оператору |
| `disconnect`, `reconnect`, `alone` | Имитировать потерю связи, возвращение либо явно продолжить одному после отключения |
| `read`, `reading manual`, `reading 60` | Подтвердить чтение ботом или установить задержку в тиках. Изначально подтверждение ручное |
| `choices`, `choose <ключ>` | Показать допустимые реплики бота и выбрать одну из них |
| `act <ключ>`, `self <ключ>` | Запросить зарегистрированное действие за бота либо за свою роль, с проверкой условий и серверного подтверждения триггера |
| `signal <имя>`, `interact <UUID>` | Подать тестовый сигнал или проверить доступное боту взаимодействие с конкретной сущностью рядом |
| `load normal`, `load 60`, `load none` | Следующую камеру бот загрузит сразу, с задержкой или вообще не подтвердит |
| `skip` | Голос бота за пропуск уже загруженной сцены. От игрока нужен отдельный голос |
| `read-self`, `skip-self` | Диагностические аналоги завершения чтения и голоса за пропуск для роли оператора |
| `status`, `state` | Положение, связь, голоса, ID диалога и камеры либо отдельные переменные, цели, Once и контрольные точки обоих персонажей |
| `reset confirm` | Удалить только свой тестовый прогресс, в том числе его временную и резервную копии. Затем снова выполнить start, выбрать роль и подтвердить готовность |

Чтобы проверить зону, оставьте бота снаружи через `stay`, войдите внутрь, затем выполните `here`. Попробуйте также оставить бота в другом измерении. Чтобы проверить голосование, дайте игроку и боту разные ответы, а затем смените один ответ на совпадающий. Для обоих ответов нужны действительные варианты из предыдущего события.

## Три готовые тестовые ветки

В отдельном тестовом мире поместите [каталог примера](examples/duo-final-events.json) под именем `whiteout-story-events.json` в корень сохранения. В отдельном клиентском профиле скопируйте содержимое [примеров для клиента](examples/duo-client/config/whiteout) в `config/whiteout`. В комплекте три коротких файла камеры и три диалога. Если уже есть свой `dialogues.json`, добавьте записи из объекта `dialogues` в свой файл. Перезапустите профиль и сервер после установки файлов.

Начните за FIRST рядом с `12 64 1` в обычном мире. В демонстрационной зоне нужны свободные клетки и пол около Y=63. Войдите в область около `0 64 1` вместе с ботом. У первого персонажа откроется его диалог. Через `choices` можно увидеть варианты второго персонажа. Если играете за SECOND, выбирайте на экране лично, а для первого персонажа подтвердите чтение командой `read`.

| Отдельный прогон | Действия | Сохранённый результат |
|---|---|---|
| Выстрел | Второй выбирает `dialogue_choice:final_second:0:0` | `whiteout:ending/loss` и камера `final_loss` |
| Пощада | Пропустите письмо, второй выбирает `dialogue_choice:final_second:0:1` | `whiteout:ending/mercy` и камера `final_mercy` |
| Письмо | Перед встречей зайдите с ботом к `-12 64 1`. Второй принимает `dialogue_choice:letter:0:0`. Затем вернитесь к встрече и выберите пощаду | Личная цель письма завершается у второго, приоритетная ветка выбирает `whiteout:ending/letter` |

Между прогонами используйте `reset confirm`. До завершения камеры можно вызвать disconnect и reconnect. При отсутствии файла клиент сообщает об ошибке. При отсутствии ответа сервер ждёт до 200 тиков, затем отсчитывает сцену без камеры этого участника и применяет обычные условия события завершения. Такой переход не завершает событие досрочно. При паузе отключённого участника сюжет продолжит ждать reconnect или явного alone.

## Перенос прежних событий и границы проверки

Для инвентаризации старого каталога запустите `python tools/migrate_story_triggers.py triggers.json --dialogues dialogues.json --scenes cutscenes --audit`. Отчёт перечислит ключи, виды и задержки либо укажет проблемные записи. Для создания нового каталога замените `--audit` на `--output candidate.json`. Сверьте результат с рабочим каталогом карты. ENTER_BOX, EXIT_BOX, SIGNAL, взаимодействия по UUID, задержки и достижимые варианты диалогов проходят через проверяемые привязки. Неизвестные эффекты и произвольные команды требуют ручного переноса; конвертер указывает причину отказа.

Бот не имеет сетевого соединения, обычного инвентаря, физики движения и собственного аудио или экрана. Виртуальное присутствие использует его координаты и измерение. Недоступные персональные показатели погоды, холода или укрытия в отдельной от оператора позиции не подтверждают условия. Для визуальной синхронизации на двух машинах, задержек реальной сети, звука, личных уведомлений на физическом втором экране и взаимодействия двух инвентарей нужен прогон двумя клиентами. Диалоговые подтверждения и незавершённые голоса находятся в памяти сессии. После полного выхода и повторного включения сохраняются прогресс, Once и курсор сцены; для повторения прерванной одноразовой диалоговой развилки может понадобиться новый тестовый прогон.
