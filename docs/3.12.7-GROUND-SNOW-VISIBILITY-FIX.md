# Whiteout 3.12.7 — GroundSnow visibility hotfix

Only GroundSnow.java was changed. The existing snowstorm renderer, shader/depth mixins, doors, electrical system and zone editor were not modified.

## Problems found from source review

* MOTION_BLOCKING heightmap is not reliable for identifying non-solid 1-layer snow. WORLD_SURFACE instead identifies the highest non-air cover.
* Checking isSkyVisible at the flake position could test the same voxel as a partial snow layer. Now the sky test runs above the covered block, while particle altitude is taken from the real 1-8 layer snow height.
* Very small flake sprites (.035-.08) and a wide spawn area produced an almost invisible effect. Sprites are now .16-.28, spawn area reduced to 24x24, and some spawn in small groups aligned with the existing wind direction.
* Added a read-only diagnostic command, no spam to the log.
* Guards missing zone snapshots on initial login/world transitions.

## Manual smoke test

1. Build the full Whiteout 3.12.7 project with Gradle 8.10.2, Java 21, Fabric 1.21.1.
2. In a COPY of your world, enable the ground snow feature with `/whiteout-ground-snow enabled true` and set `/whiteout-ground-snow intensity 100`.
3. Stand on an open area with `snow_block` or `snow` layers. Start a Whiteout blizzard.
4. Watch visible ground-hugging horizontal streams for 10-20 seconds. Run `/whiteout-ground-snow stats` and confirm `created` is >0 and `active` is nonzero. These counters count particles supplied to the manager, not guaranteed GPU draw calls.
5. Test 1-layer and 8-layer snow, sheltered areas, nighttime, different zone heights, moving camera, and a zone boundary.
6. With Iris/BSL and without shaders, check snow, glass, sky and NPC occlusion and FPS. Also test `Minimal` and `Decreased` particle settings.
7. After login/logout and a change of dimensions, the counters reset. No `VerifyError` should appear.

If `created` stays at 0: `no snow` suggests ground/height rejection, `no sky` a roof or sky test, `shelter` a shelter zone, `no zone` unmatched weather bounds, `weak weather` insufficient actual storm intensity. Compare the counters before/after 10 seconds. If `created` is positive but invisible, focus on particle rendering and depth.
